# Unity 导出工程真机部署 · 实战复盘

> 📅 日期：2026.5.11（夜）
> 🏷️ 标签：技术、Unity、iOS、Xcode、部署、实战
> 📝 摘要：Xcode 26.3 + Unity 6000.3.8f1 + iPhone 15 Pro，从桌面 `Unity_PJ_Z_Build_iOS` 工程目录跑通命令行一条龙打包 + 装机，踩过 6 个坑全部修好。

---

## 结论 / 精华

- **最终方案是命令行，不是 Xcode GUI**。GUI 报错不透明，命令行错误可读且能用参数覆盖配置
- 一共踩了 6 个坑：`xcode-select 指向 CLT` / `设备 ID 双体系` / `脚本沙箱拦 IL2CPP` / `磁盘不足` / `缺 StoreKit 链接` / `il2cpp.a 幻影错误`
- 真正的修复只需要在 `xcodebuild` 命令上加两个参数：`ENABLE_USER_SCRIPT_SANDBOXING=NO` 和 `OTHER_LDFLAGS='$(inherited) -framework StoreKit'`
- 装机命令就一行：`xcrun devicectl device install app ...`
- **每次 Unity 重新导工程后这些坑都会重现**（因为 Unity 覆盖 pbxproj），所以走命令行最省心

## 本次完整操作流程（按执行顺序）

### 第 1 步：修好 xcode-select 指向

发现问题：
```
xcode-select: error: tool 'xcodebuild' requires Xcode,
but active developer directory '/Library/Developer/CommandLineTools'
is a command line tools instance
```

修复（需要 sudo 密码，首次永久生效）：
```bash
sudo xcode-select -s /Applications/Xcode.app/Contents/Developer
```

验证：
```bash
xcode-select -p        # 应输出 /Applications/Xcode.app/Contents/Developer
xcodebuild -version    # 应显示 Xcode 版本号
```

### 第 2 步：确认设备和签名

```bash
xcrun devicectl list devices                          # 拿 CoreDevice UUID（装 App 用）
security find-identity -v -p codesigning              # 确认有 "Apple Development: xxx" 可用
```

如果手机显示 `available` 不是 `connected`，去手机上解锁 + 点"信任这台电脑"。

### 第 3 步：清理磁盘（这次才遇到，以后看情况）

本次 `/System/Volumes/Data` 只剩 8.4 GB，Unity IL2CPP 编译时会因 `.o.tmp` rename 失败。至少需要 **20 GB** 可用。

安全清理：
```bash
rm -rf "$HOME/Library/Developer/Xcode/iOS DeviceSupport"  # ≈ 4.5 GB，下次连机自动重建
rm -rf "$HOME/Library/Developer/Xcode/DerivedData"/*      # 其他工程的缓存
rm -rf "/Users/typori_mac/Desktop/Unity_PJ_Z_Build_iOS/build"
rm -rf "/Users/typori_mac/Desktop/Unity_PJ_Z_Build_iOS/Il2CppTempDirArtifacts"
df -h /System/Volumes/Data  # 确认可用空间
```

不够的话继续删 `~/Library/Caches` 里的大头，或者去 *关于本机 → 存储空间 → 管理* 看最占地方的分类（常见大户：iPhone Backup、Downloads、旧 Xcode Archives）。

### 第 4 步：命令行打包（核心）

```bash
cd /Users/typori_mac/Desktop/Unity_PJ_Z_Build_iOS

xcodebuild \
  -project Unity-iPhone.xcodeproj \
  -scheme Unity-iPhone \
  -configuration ReleaseForRunning \
  -destination 'id=00008130-000839CC2E20001C' \
  -allowProvisioningUpdates \
  -derivedDataPath ./build/DerivedData \
  ENABLE_USER_SCRIPT_SANDBOXING=NO \
  OTHER_LDFLAGS='$(inherited) -framework StoreKit' \
  clean build
```

参数说明：
- `-destination 'id=...'` 用的是 **xcodebuild 的老 ID 体系**，不是 devicectl 的 UUID
- `-allowProvisioningUpdates` 让 Xcode 自动处理描述文件
- `-derivedDataPath ./build/DerivedData` 把中间产物关到工程目录里，避免和其他工程串
- `ENABLE_USER_SCRIPT_SANDBOXING=NO` —— **不传这个会必死**，IL2CPP 工具链会被系统沙箱拦截
- `OTHER_LDFLAGS='$(inherited) -framework StoreKit'` —— **不传这个会链接失败**，Unity Purchasing 插件需要 StoreKit 但 Unity 导出工程没配
- 首次 build 或改动大的时候加 `clean`；只是出新包可以去掉 `clean`（快 3~10 分钟）

耗时参考（iPhone 15 Pro arm64，本机）：
- 带 clean 全量：~5 分钟（IL2CPP 编 760 个 C++ 文件约 2-3 分钟）
- 不带 clean 增量：~1 分钟

成功标志：日志末尾看到 `** BUILD SUCCEEDED **`。

### 第 5 步：装到手机

```bash
xcrun devicectl device install app \
  --device 6604E055-4DCA-5729-83D4-28F9B2BF5DD9 \
  /Users/typori_mac/Desktop/Unity_PJ_Z_Build_iOS/build/DerivedData/Build/Products/ReleaseForRunning-iphoneos/UnityPJZTemp.app
```

成功标志：输出 `App installed:` + bundleID + installationURL。

### 第 6 步：首次信任开发者（手机操作）

iPhone 上：**设置 → 通用 → VPN 与设备管理 → 开发者 App → `Apple Development: 383103897@qq.com` → 点信任**

之后点图标（名字是 `UnityPJZTemp`）就能启动。

## 踩坑全表（按遇到顺序）

| # | 现象 | 根因 | 修复 |
|---|---|---|---|
| 1 | `xcodebuild requires Xcode, but active directory is CommandLineTools` | `xcode-select` 指向 CLT | `sudo xcode-select -s /Applications/Xcode.app/Contents/Developer` |
| 2 | `Unable to find a device matching the provided destination specifier` | Xcode 26 新 CoreDevice UUID ≠ xcodebuild 的老 ID | 用 xcodebuild 报错里列出的那个 `00008130-...` |
| 3 | `no such file or directory: il2cpp.a` | 幻影错误，真实原因是 #4 脚本失败导致产物没生成 | 见 #4 |
| 4 | `Failed to load libhostfxr.dylib (file system sandbox blocked open())` | Xcode User Script Sandboxing 拦截 IL2CPP 工具链加载 .NET host 动态库 | 传 `ENABLE_USER_SCRIPT_SANDBOXING=NO` |
| 5 | `il2cpp build failed due to an internal error` + `Rename failed: .o.tmp -> .o` + `disk I/O error` | 磁盘空间不足（Bee backend 原子重命名失败） | 清出 ≥ 20 GB 空间 |
| 6 | `Undefined symbols: _OBJC_CLASS_$_SKProductsRequest ... in UnityPurchasing.o` | UnityFramework 没链 StoreKit.framework，但 Unity Purchasing 插件需要 | 传 `OTHER_LDFLAGS='$(inherited) -framework StoreKit'` |

## 需要注意的几条经验

1. **不要同时用 Xcode GUI 和命令行 build 同一个工程**。会抢 `build.db` 导致 `disk I/O error`（即便空间够）。命令行接管前把 Xcode 里正在跑的构建 ⌘. 停掉，不用关 Xcode。
2. **Unity 每次重新导工程都会覆盖 pbxproj**，坑 4 / 6 会重现。所以不要去改工程文件，每次命令行传参最稳。
3. **调错时先别 clean**。IL2CPP 全量编译最慢，保留产物增量改错误参数可以 1 分钟一轮。
4. **命令行产物目录 ≠ scheme 名**。scheme 叫 `Unity-iPhone`，但 `.app` 叫 `UnityPJZTemp.app`（取自 `PRODUCT_NAME`）。装机时别找错文件。
5. **免费 Apple ID 签名有效期 7 天**。过期后手机上图标还在但点开就闪退，重新跑第 4-5 步装一次就行。
