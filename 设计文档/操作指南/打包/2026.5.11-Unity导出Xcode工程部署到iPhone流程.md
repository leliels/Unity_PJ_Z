# Unity 导出 Xcode 工程部署到 iPhone 完整流程

> 📅 日期：2026.5.11
> 🏷️ 标签：技术、Unity、iOS、Xcode、部署
> 📝 摘要：Unity 导出的 Xcode 工程如何通过 Xcode 部署到自己的 iPhone 上，含常见报错处理。

---

## 背景 / 问题

从 Unity 导出 iOS 工程后，用 Xcode 打开，想把 app 装到自己连接的 iPhone 上真机测试，但没做过这件事，需要一份从零到运行的完整流程。

## 结论 / 精华

- **核心 7 步**：登录 Apple ID → 配签名 → 连手机并信任 → Xcode 顶栏选手机 → 点 ▶️ 运行 → 手机上信任开发者 → 启动
- **免费 Apple ID 就够用**，但装上的 app **只能用 7 天**，过期要再用 Xcode 装一次
- **常见拦路石**：Bundle Identifier 冲突、勾了免费账号不支持的能力（如 In-App Purchase）、iOS 版本比 Xcode 新
- **不用管命令行 `xcode-select`**，那个只影响命令行检查，不影响 Xcode 图形界面 build
- 报错不要慌，90% 都是签名配置问题，按下面"常见坑"对照处理

---

## 详细内容

### 前置条件

- Mac（装好 Xcode，从 App Store 下载即可）
- Unity 已导出 iOS 工程（里面有 `Unity-iPhone.xcodeproj`）
- 一根**数据线**（能传数据的，不是纯充电线；原装线基本都行）
- 一个 **Apple ID**（免费账号就够，能装到自己手机上用 7 天；付费开发者账号 99 美元/年可长期用）
- 手机能连上 Mac 并解锁

---

### 第 1 步：Unity 里 Build 出 Xcode 工程

Unity → File → Build Settings → 选 iOS → Build
（这一步前提已完成）

### 第 2 步：打开 Xcode 工程

双击 Unity 导出文件夹里的 `Unity-iPhone.xcodeproj`，Xcode 会自动打开。

### 第 3 步：登录 Apple ID（只需要做一次）

1. Xcode 菜单栏 → `Xcode` → `Settings...`（老版本叫 `Preferences...`）
2. 选 `Accounts` 标签页
3. 左下角 `+` → `Apple ID` → 登录你的 Apple ID

### 第 4 步：配置签名

1. 左侧项目导航器最顶上，点蓝色的 `Unity-iPhone` 图标
2. 中间区域 TARGETS 下选 `Unity-iPhone`
3. 顶部选 `Signing & Capabilities` 标签
4. 勾选 `Automatically manage signing`
5. `Team` 下拉里选你刚登录的 Apple ID（会显示成 `你的名字 (Personal Team)`）
6. 看 Status 区域：
   - 绿色勾或无报错 → 继续第 5 步
   - 有红字 → 对照下方"常见坑"处理

#### Bundle Identifier 命名建议

如果报 Bundle Identifier 冲突，改成独特的：
- 格式：`com.你的昵称.游戏名`（只能用字母数字和点，不能有空格和中划线在某些位置）
- 例：`com.typori.MyGame`

### 第 5 步：连接手机

1. 数据线插上，手机解锁
2. 手机弹"信任此电脑" → 点**信任**，输入锁屏密码
3. Xcode 顶部中间的运行目标下拉框（默认可能是 `Any iOS Device` 或某个模拟器），点一下 → 选你手机的名字

### 第 6 步：点运行

- 左上角 ▶️ 按钮，或快捷键 `Cmd + R`
- 等编译（Unity 工程第一次可能要 5-15 分钟）
- app 会自动装到手机并尝试启动

### 第 7 步：信任开发者证书（第一次运行必做）

第一次启动时手机会报"未受信任的企业级开发者"或"无法打开"。

1. 手机 → 设置 → 通用 → VPN 与设备管理
2. 找到你的 Apple ID（会在"开发者 App"分组下）
3. 点进去 → **信任** → 确认
4. 从手机桌面点 app 图标启动

## 常见坑

### 坑 1：Personal Team 不支持 In-App Purchase（本次实际遇到）

**报错**：`Personal development teams do not support the In-App Purchase capability.`

**原因**：免费 Apple ID 不支持内购能力，但 Unity 工程默认勾选了。

**解决**：
1. 在 `Signing & Capabilities` 标签里往下滚
2. 找到 `In-App Purchase` 卡片
3. 鼠标移到它标题栏，右侧出现 `×` 图标，点掉删除这个能力
4. 回到上面点 `Try Again`

> 同类能力（Push Notifications、Game Center、iCloud 等）免费账号也大多不支持，遇到就一起删。

### 坑 2：Bundle Identifier 冲突

**报错**：`The app could not be registered... identifier is not available`

**解决**：改成独一无二的，比如 `com.typori.你的项目名`。

### 坑 3：免费账号签出来的 app 7 天就失效

**解决**：
- 过期后把手机连上 Mac，再用 Xcode 点一次运行即可刷新
- 长期用要买付费开发者账号（99 美元/年）

### 坑 4：iOS 版本比 Xcode 支持的新

**报错**：`Could not locate device support files` 之类

**解决**：升级 Xcode 到最新版（App Store 里更新）。

### 坑 5：手机没被 Xcode 识别

**排查**：
- 数据线是不是数据线（不是纯充电线）
- 手机有没有解锁并点过"信任此电脑"
- 换个 USB 口试试
- Xcode → Window → Devices and Simulators，看手机有没有出现在列表里

### 坑 6：编译报 Swift / 脚本权限相关错误

Unity 导出 iOS 工程的老毛病。把具体报错信息复制出来搜一下基本都有解，或者问 AI。

### 坑 7：Unity 6 + Xcode 26 的 UnityFramework header 错误（本次实际遇到）

**报错**：
```
UnityFramework.h:70:1: error: umbrella header for module 'UnityFramework' 
does not include header 'AppDelegateListener.h'
... does not include header 'RedefinePlatforms.h'
... does not include header 'UndefinePlatforms.h'
... does not include header 'UnityViewControllerListener.h'

AppDelegateListener.h:3:10: error: double-quoted include "LifeCycleListener.h" 
in framework header, expected angle-bracketed instead

大量 expected a type / expected identifier or '(' 错误
```

**根因**：Unity 6.3.x 导出的 framework public header 在 Xcode 26 严格 module verification 下通不过。这几个文件设计上是 framework 内部用的，不应该被当作 public header 暴露。

**解决（推荐做法，不改代码）**：

把以下 4 个文件的 `Target Membership` 从 `Public` 改成 `Project`：

- `Classes/PluginBase/AppDelegateListener.h`
- `Classes/PluginBase/UnityViewControllerListener.h`
- `Classes/RedefinePlatforms.h`
- `Classes/UndefinePlatforms.h`

操作步骤：
1. Xcode 左侧文件树点中文件
2. 右侧 Inspector（`Cmd + Option + 0` 打开）
3. `Target Membership` 区域，找到 `UnityFramework` 行
4. 右边下拉框从 `Public` 改成 `Project`
5. `Shift + Cmd + K` Clean，再 `Cmd + R`

如果之后又冒出别的 `umbrella header for module 'UnityFramework' does not include header 'XXX.h'`，把 `XXX.h` 也照样改成 `Project`。

**错误修法（不要走的弯路）**：
- 把 `Defines Module` 改成 `No` —— 会导致 `il2cpp.a` 链接找不到，报 `Command Ld failed`
- 改 Allow Non-modular Includes In Framework Modules = Yes 是有用的，可以保留

### 坑 8：Command Ld failed with a nonzero exit code

**报错**（展开 build log 后看到）：
```
clang++: error: no such file or directory: '.../il2cpp.a'
```

**原因**：`UnityFramework` 的 `Defines Module` 被改成 `No` 了，破坏了 GameAssembly → UnityFramework 的依赖链，导致 il2cpp.a 还没生成就被链接。

**解决**：把 `UnityFramework` target 的 `Defines Module` 改回 `Yes`，然后用「坑 7」的办法解决头文件错。

### 调试技巧：怎么看完整 build 日志

Issue Navigator（`Cmd + 5`）里看到的报错经常被截断或归并。要看真实日志：

1. 左侧栏点 **气泡图标**（Report Navigator，`Cmd + 9`）
2. 点最上面那条最新的 `Build Unity-iPhone`
3. 顶部过滤器选 `Errors Only`
4. 找到具体 build 阶段（如 Ld、Compile XXX.m），点右边出现的 `≡` 图标展开完整命令和输出
5. 也可以直接把整个 log 导出成 txt 文件分析（右键 build 记录 → Export...）

## 关于 `xcode-select`（补充概念）

macOS 上有两套苹果开发工具：

1. **Xcode.app**（从 App Store 下载的，带图形界面）
2. **Command Line Tools**（纯命令行工具包，体积小）

`xcode-select` 是个指路牌，告诉系统命令行工具优先去哪一套里找。

- **正常图形界面用 Xcode build 不受影响**，不用管
- 只有在命令行跑 `xcodebuild`、`devicectl` 等命令时才相关
- 如果要切到完整 Xcode：`sudo xcode-select -s /Applications/Xcode.app/Contents/Developer`
