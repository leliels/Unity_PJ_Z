## 步骤

### 步骤 0 · 环境自检（必做，约 10 秒）

```bash
xcode-select -p
xcodebuild -version
df -h /System/Volumes/Data | tail -1
xcrun devicectl list devices 2>/dev/null | grep connected
```

通过条件（全部满足才能继续）：
- `xcode-select -p` 输出 `/Applications/Xcode.app/Contents/Developer`（**不**是 CommandLineTools）
- `xcodebuild -version` 能正常显示版本
- 可用空间 **≥ 20 GB**
- `devicectl list devices` 里能看到目标 iPhone 是 `connected` 状态

不通过 → 跳到对应的"异常处理"。

### 步骤 1 · 打包（核心命令，后台跑）

```bash
cd /Users/typori_mac/Desktop/Unity_PJ_Z_Build_iOS

nohup xcodebuild \
  -project Unity-iPhone.xcodeproj \
  -scheme Unity-iPhone \
  -configuration ReleaseForRunning \
  -destination 'id=00008130-000839CC2E20001C' \
  -allowProvisioningUpdates \
  -derivedDataPath ./build/DerivedData \
  ENABLE_USER_SCRIPT_SANDBOXING=NO \
  OTHER_LDFLAGS='$(inherited) -framework StoreKit' \
  build > /tmp/unity_build.log 2>&1 &
echo "PID=$!"
```

> **不要加 `clean`**（除非用户明确要求干净重编）。增量 build 通常 1-3 分钟就好，clean 要 5-10 分钟。

轮询（每 60 秒一次，直到 `BUILD SUCCEEDED` / `BUILD FAILED`）：

```bash
sleep 60
ps -p <PID> -o pid,etime,stat 2>&1 | head -5
grep -E "BUILD SUCCEEDED|BUILD FAILED|error:" /tmp/unity_build.log | tail -5
```

成功标志：日志末尾 `** BUILD SUCCEEDED **`。

失败处理：看日志中第一个 `error:` 对照"异常处理"。

### 步骤 2 · 装到手机

```bash
xcrun devicectl device install app \
  --device 6604E055-4DCA-5729-83D4-28F9B2BF5DD9 \
  /Users/typori_mac/Desktop/Unity_PJ_Z_Build_iOS/build/DerivedData/Build/Products/ReleaseForRunning-iphoneos/UnityPJZTemp.app
```

成功标志：输出 `App installed:` 且带 `installationURL`。

### 步骤 3 · 提示用户信任（必给）

原话发给用户：

> App 已装到手机。首次启动前请在 iPhone 上操作：
> **设置 → 通用 → VPN 与设备管理 → 开发者 App → `Apple Development: 383103897@qq.com` → 点信任**
> 之后点图标 `UnityPJZTemp` 就能启动。

## 异常处理（按报错关键词查）

### E1. `xcodebuild requires Xcode, but active directory is CommandLineTools`

执行（需要用户输密码）：
```bash
sudo xcode-select -s /Applications/Xcode.app/Contents/Developer
```
sudo 密码无法在非 TTY 环境输入 → 让用户手动跑这一条。

### E2. `Unable to find a device matching the provided destination specifier`

从 xcodebuild 报错里提取它给出的 `Available destinations` → iOS 真机那一行的 `id=XXXXX` → 替换 `XCODEBUILD_ID` 重新跑。

### E3. `Failed to load libhostfxr.dylib (file system sandbox blocked open())`

漏传 `ENABLE_USER_SCRIPT_SANDBOXING=NO`。把它加到 xcodebuild 命令。

### E4. `no such file or directory: il2cpp.a` / `Command Ld failed`

这是 **幻影错误**，真实原因在日志更靠前。搜：
```bash
grep -nE "Failed to load libhostfxr|Rename failed|il2cpp build failed|file system sandbox" /tmp/unity_build.log | head
```
对应去 E3 或 E5。

### E5. `Rename failed: .o.tmp -> .o` / `disk I/O error` / `il2cpp build failed due to an internal error`

磁盘不足。先清最安全的几项：
```bash
rm -rf "$HOME/Library/Developer/Xcode/iOS DeviceSupport"
rm -rf "$HOME/Library/Developer/Xcode/DerivedData"/*
rm -rf /Users/typori_mac/Desktop/Unity_PJ_Z_Build_iOS/build
rm -rf /Users/typori_mac/Desktop/Unity_PJ_Z_Build_iOS/Il2CppTempDirArtifacts
df -h /System/Volumes/Data
```
清完 < 20 GB → 让用户手动清理（Downloads / iPhone Backup / 旧 Xcode Archives）。

### E6. `Undefined symbols: _OBJC_CLASS_$_SKProductsRequest ... UnityPurchasing.o`

漏传 `OTHER_LDFLAGS='$(inherited) -framework StoreKit'`。加上重跑。

### E7. `Undefined symbols: _OBJC_CLASS_$_XXXXX` （其他缺少的 framework）

推断所属 framework：
- `SK*` → StoreKit
- `AVPlayer*` / `AVAsset*` → AVFoundation
- `CL*` (Location) → CoreLocation
- `CM*` (Motion) → CoreMotion

追加到 `OTHER_LDFLAGS`：
```
OTHER_LDFLAGS='$(inherited) -framework StoreKit -framework <新加的>'
```

### E8. `error: accessing build database "build.db": disk I/O error`（空间充足却报）

Xcode GUI 正在抢同一份产物。让用户在 Xcode 里 Product → Stop（⌘.），不用关 Xcode，然后重试。

### E9. 手机 `available (paired)` 而非 `connected`

让用户解锁手机 + 允许"信任此电脑"。

### E10. `install app` 卡在 `Enabling developer disk image services`

Xcode 首次连这台手机会拉 developer disk image，需要几分钟 + 网络。等着就行，不是报错。
